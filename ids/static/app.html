Sentinel
Overview

Real-time intrusion detection for your web application.

Sentinel inspects every request the moment it arrives, then explains each threat in plain language on a live dashboard — no log files, no guesswork.

How it works

Sentinel runs inside your website and reports to your account.

  1. 1

    A visitor sends a request

    Sentinel sits in front of your app as middleware, so it sees each request before your code does.

  2. 2

    Sentinel inspects it

    Rules check the URL, query string, body and headers, then assign a risk score from 0 to 100. Sentinel also remembers each visitor's recent behavior to spot floods and repeated failed logins.

  3. 3

    It logs or blocks

    In monitor mode threats are only recorded. In block mode a dangerous request gets a 403 and a visitor with an active behavior alert gets a 429.

  4. 4

    You see it live

    The dashboard shows an All clear, Suspicious, or Under attack status, live alerts, and blocked IPs.

Behavior alerts fire once and stay active for 2 minutes. You get one alert instead of thousands, and in block mode that visitor stays blocked meanwhile.

What it detects

Two kinds of threats: a single bad request, and a pattern that only shows over time.

In a single request

SQL and NoSQL injection
Database commands typed into forms or addresses.
Cross-site scripting (XSS)
Script code planted to run in other visitors' browsers.
Path traversal
Attempts to read files outside the web folder.
Command, PHP and template injection
Attempts to run code on your server.
Log4Shell and header injection
Including obfuscated Log4Shell strings.
Scanners and probing
Hacking tools, and searches for .env, .git or admin panels.

Over time

Flood
Far too many requests from one visitor in a short window.
Brute force
Many failed logins in a short time.
Credential stuffing
Many different usernames tried from one source.
Scanning
Many requests for pages that do not exist.

Setup

About five minutes, using any Python app built on FastAPI or Starlette.

  1. 1

    Create an account

    Open Sign in / My websites in the top bar. Passwords need at least 10 characters.

  2. 2

    Add your website

    Give it a name. Sentinel shows your API key once, so copy it right away. If you lose it, choose "New key" and the old one stops working.

  3. 3

    Add the middleware

    Paste these lines into your website's Python code:

    from ids.sdk import SentinelMiddleware

app.add_middleware(
    SentinelMiddleware,
    api_key="your-api-key",
    server="this server's address",
    mode="detect",   # use "block" to also stop attacks
)
  4. 4

    Check the dashboard

    Once your site gets its first visit, it shows as Connected. Run in detect mode for a while, then switch to block when ready.

FAQ

Short answers to the usual questions.

What is the difference between detect and block mode?

Detect only records threats. Block also stops them: a dangerous request gets a 403 response, and a visitor with an active behavior alert gets a 429 for the next 2 minutes.

What does Sentinel store about my visitors?

The page path (never the query string), a short redacted snippet of the evidence, the visitor's IP address and browser name. It never stores request bodies, cookies, passwords or usernames.

Could a normal visitor get blocked by mistake?

Rules are tested against harmless lookalikes, but no detector is perfect. That is why monitor mode comes first: you can review alerts before turning on blocking.

I lost my API key. What now?

Open your website under My websites and choose "New key". The old key stops working immediately, so update your site with the new one.

Where do I see what is happening?

Choose "Open dashboard" on any website under My websites. It updates live without refreshing.
